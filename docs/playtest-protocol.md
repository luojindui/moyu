# 试玩闭环协议（v2，2026-11-27 定稿）

## 总则

每批功能完成后，起 **6 个不同性格的 subagent 玩家**，**每人体验两次**（初玩 + 复验），通过门槛后才进下一批。

## 每轮流程

```
[1] 6 个新 agent 并行「初玩」（各自独立任务书 + 线上 URL）
        ↓
[2] 收 6 份报告 → 汇总分诊（VALID / INVALID / UNCERTAIN）→ 修 P0/P1
        ↓
[3] 同样这 6 个 agent「复验」（send_message 续会话，保留第一次记忆）
        ↓
[4] 复验报告 → 若仍有 P0 → 再修再验；无 P0 且达标 → 进下一批
```

- **同一个 agent 连做两次**：第二次用 `send_message` 续会话，它会记得自己上次提的问题，复验时能指出"修没修好"，比新 agent 更有判断力
- 两次之间我做的修改会推到同一个线上 URL，agent 复验时看到的是修复后的版本

## 验收门槛（三条全过）

| 门槛 | 标准 |
|---|---|
| 平均分 | **复验轮的 6 人平均分 > 8/10** |
| 阻塞问题 | **0 个 P0**（会导致玩不下去/数据错误/严重卡顿） |
| 可用共识 | ≥ 4/6 明确写"可交付：是" |

- 分数以**复验轮**为准（初玩分数作为基线，用于说明修复效果）
- 任一门槛不过 → 继续修，修完再复验（同一批 agent，最多 3 次）

## 每轮 6 人配置

批次与性格对应见下表。同一性格**不连续两轮出现**，保证每批有新鲜视角。

| 批次 | 内容 | 6 个性格 |
|---|---|---|
| 批 1 | 同事系统 + 天赋树 | 管理党、构筑党、碎片党、弃坑型、审计党、数据党 |
| 批 2 | 每日事件卡 + 回合制老板 | 赌徒党、叙事党、操作党、碎片党、审计党、弃坑型 |
| 批 3 | 工位经营 + 每日精力 | 收集党、管理党、硬核党、碎片党、审计党、无障碍党 |
| 批 4 | 摸鱼站小游戏 | 操作党、碎片党、弃坑型、收集党、审计党、数据党 |
| 终验 | 全部 7 系统 | 硬核、碎片、弃坑、管理、构筑、赌徒、收集、审计（8 人） |

## 每个 agent 的任务书模板（必含）

1. **你是谁**：性格 + 过去的游戏经验 + 审美偏好
2. **怎么玩**：线上 URL、操作说明、关键数值
3. **关注点**：本批新增系统 + 该性格最在意的 3 件事
4. **能做什么**：可跑引擎探针（`playtest/` 下建文件）、可截图分析、可用 `__MOYU__` 钩子（dev 环境）
5. **输出格式**：评分维度 + 问题清单（P0/P1/P2 + 证据）+ 新需求建议（含实现代价）+ "可交付：是/否"
6. **禁止**：不得修改 `src/`

## 分诊规则

| 判定 | 处理 |
|---|---|
| VALID（真问题） | P0/P1 必修；P2 记入待办 |
| INVALID（误报/已修） | 在复验时向 agent 说明，请它复核 |
| UNCERTAIN（数据不足） | 我补充探针验证后再定 |

## 12 个性格池

|---|---|---|
| 1 | 碎片党 | 通勤 2 分钟、一天 5 次能否玩到东西 |

| 6 | 操作党 | 小游戏、反应、手感 |
| 7 | 叙事党 | 剧情、角色、文字 |
| 8 | 收集党 | 图鉴、装修、成就、看得见的成长 |
| 9 | 弃坑型 | 3 分钟不爽就删（最严格） |
| 10 | 审计党 | 找 bug、规格符合度、边缘情况 |
| 11 | 无障碍党 | 中老年/色弱/读屏/单手 |
| 12 | 数据党 | 统计一致性、导出、信任 |
