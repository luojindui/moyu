## P1 清单

### P1-1 横屏「建议竖屏」提示恒不显示（CSS 层叠顺序错误），且横屏画布仅 98px
- 位置：`src/style.css:730-737`
- 现象：媒体查询块写在基础规则**之前**——
  ```css
  @media (orientation: landscape) and (max-height: 560px) { #rotate-hint { display: block; } }  /* 730 */
  #rotate-hint { display: none; ... }                                                          /* 735 */
  ```
  同优先级后者胜，`display` 永远是 `none`；实测 844×390 横屏 `rotateHint = "none"`、画布高 98px、商店占 161px。玩家横屏时画面被压到很矮，却收不到任何「建议竖屏」提示。
- 建议：把 `#rotate-hint` 基础规则移到媒体查询之前，或提高媒体查询内选择器优先级（如 `body #rotate-hint`）。
- 证据：`out/mobile-report.json` M25/M26；`out/M-landscape.png`。

## 剩余 P2（记录，不阻塞交付）

### P2-1 回合制老板「已作答过」后，再超时不再提示「没来得及选…这次不算」
- 位置：`src/main.ts:795`（`if (!wasOpen && bossPanel.isOpen) choicePickedThisRound = false;`）+ `795-800`
- 原因：`wasOpen` 在 `bossPanel.sync()` 之前捕获，该行恒为假（死代码）；而答题后面板由 `showResult` 的 260ms `setTimeout` 关闭，HUD 150ms tick 观察不到「开→关」跃迁，`choicePickedThisRound` 保持 `true`，于是下一次超时进入 `if (!choicePickedThisRound)` 分支时被跳过。
- 影响：仅「超时提示」缺失（无奖无罚、连胜不变），首次超时正常（H16 ✅）。属于反馈缺失，不影响数值。
- 修法：把复位移到 `bossPanel.sync(es)` 之后（用 sync 后的 `isOpen` 比较），或在 `show()` 新一轮开始时复位。
- 证据：`out/e2e-report.json` H15；专项探针 `probe-boss-timeout2.mjs`（首次超时 toast 命中、作答后再超时 log 为空）。

### P2-2 存档 `levels` 未过滤未知升级 id
- 位置：`src/engine/save.ts:141`（只校验「正整数 ≤ MAX_LEVEL」，未校验 id ∈ UPGRADES）
- 现象：篡改档写入 `levels: { hack: 5 }` 会被保留（`{"hack":5}`）；引擎/商店只遍历已知 UPGRADES，因此无实际收益，但脏数据进存档、与「只接受已知键」的注释意图不符。
- 建议：过滤 `UPGRADES.some(u => u.id === k)`。
- 证据：`out/e2e-report.json` K7b。

### P2-3 每日首开天赋点提示被改成新手文案（本轮修复批引入的回归）
- 位置：`src/main.ts:702` → `showToast("戳屏幕摸鱼，攒够 15 解锁第一件升级")`
- 现象：`grantDailyTalentPoint` 每天首开都会触发，但文案是首日新手引导；老玩家每天都会看到「戳屏幕攒 15」的提示，且**不再知道今天领到了 1 个天赋点**（仅 👥 上有「天赋」角标）。
- 建议：文案按状态区分（新号显示引导；老号显示「今日天赋点 +1」），或恢复原提示。
- 证据：代码审阅 + `playtest/r16-*.json` 历史证据中旧文案为「送你 1 个天赋点，点 👥 看看」。

### P2-4 「首日全额」文案已成死分支；首日的家具/天赋/卡离线加成被 95% 硬上限吞掉
- 位置：`src/ui/welcome.ts:21`（`rate >= 1 ? "首日全额"`）；`src/engine/progression.ts:21/40/58`（`OFFLINE_MAX = 0.95`，首日 `min(0.95, 1+加成)`）
- 现象：0e546f5 引入 95% 硬上限后，`rate` 恒 ≤ 0.95 → 「首日全额」永不显示（实测首日显示「离线效率 95%」），且首日的离线加成（地毯 +5% 等）因 `min(0.95, 1+加成)` 恒被压平、完全无感。这与 6f09a50「首日地毯要生效」的修复意图冲突；若为平衡决策则需产品确认并清理死文案。
- 证据：`out/e2e-report.json` J17（「离线效率 95%｜12 小时封顶」）；`src/engine/progression.ts:40`。

### P2-5 极值篡改档的 HUD 显示为科学计数法（仅篡改可达，不崩）
- 现象：`moyu=1e308` 时 HUD 显示 `1e+300亿`（`formatMoyu` 大数分支直接 `toFixed(2)` 未做指数保护）。无 NaN/Infinity、可继续操作。
- 建议：`formatMoyu` 对 `n >= 1e21` 走指数或上限显示。
- 证据：`out/e2e-report.json` K16。

### P2-6 dev-only `__MOYU__.forceBoss()` 返回值是「旧变体」
- 现象：该钩子返回 `es.bossVariant`（尚未被 `forcedVariant` 覆盖前），返回值不代表本次强制结果；仅影响探针/调试，不影响生产包。
- 证据：`probe-boss-timeout2.mjs` 中 `forced: "hold"` 但实际出现的是 choice 面板。
