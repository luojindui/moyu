## 1. 奖励对比表

公式（minigames.ts:65）：`reward = floor((idle*0.6 + 20) × score/100)`，score 上限 9999。
满分口径（引擎实算）：节奏 1475、咖啡 660–820（局内掉落 33–41，理论 1060）、找老板 549。
一次派遣口径：最早可用「老周 Lv1 + 就近溜达」（153s，×2.2，无匹配）。

| 阶段 | 挂机/s | 30s 挂机 | 节奏满分奖励 | 占 30s 挂机 | 一次派遣 | 节奏占派遣 | 折算挂机秒数 |
|---|---|---|---|---|---|---|---|
| 早期 | 1 | 30 | 303 | **10.1×** | 660 | 46% | 303s |
| 中期 | 1,000 | 30,000 | 9,145 | **0.305×** | 4,599 | 199% | 9.1s |
| 后期 | 100,000 | 3,000,000 | 885,295 | **0.295×** | 442,743 | 200% | 8.9s |
| （参考）开局 | 0.2 | 6 | 296 | 49.3× | 660 | 45% | 1480s |

咖啡/找老板满分占同期 30s 挂机：咖啡 5.6× / 16.9% / 16.4%；找老板 3.77× / 11.3% / 11.0%。
3 次/天全节奏：早期 909（10.1× 90s 挂机）、中期 27,435（30.5%）、后期 2,655,885（29.5%）。

- 盈亏平衡分数（=30s 挂机）：早期 145.6 分可达；中期 4,838.7 / 后期 4,998.3 分**不可达**。
- 引擎注释目标 18s 挂机/局：开局实际 82.2×、早期 16.8×、中期 0.51×、后期 0.49×。
- 阶段漂移：早期→后期，同一满分折算挂机秒数 303s→8.9s，**34.2×**。
- 若真打满 cap 9999：2,011 / 61,993 / 6,001,399（68.6× / 2.07× / 2.0× 30s 挂机）——与实测最高分差 7 倍量级。

## 2. 三游戏期望分对比

| 游戏 | 理论上限 | 现实期望（当前实现） | 保底 | 备注 |
|---|---|---|---|---|
| 节奏点击 | 1475（引擎口径 1180） | 590（250ms 乱点）→ 900 → 1250 → 1475 | **590** | 无 miss 惩罚；UI 每 perfect 额外 +5 |
| 接咖啡 | 660–820（理论 1060） | 150–382（视觉错位只能盲点，模拟 3000 局） | ~0 | 修好视觉后 516–665 |
| 找老板 | 550（现实 548–549） | 400–548（几乎恒定） | 400 | 实测 0.3ms 点完 5 轮即结束 |

**最优策略**：每天 3 次全部打节奏点击；不存在 2+1/1+1+1 分配（奖励对分数线性、三游戏同系数、次数共享、无边际递减 → 单次 argmax × 3）。
**是否有唯一最优**：有。`节奏乱点保底 590 > 找老板理论上限 550` → 找老板被严格支配；咖啡在当前实现期望 ≤382，修视觉后 516–665 仍低于节奏熟练线。且因“中途退出不消耗次数”，实际最优操作是重开到高分再结算（≈上限）。

## 3. 刷分空间

| 项目 | 结论 | 证据 |
|---|---|---|
| 分数上限 9999 | 不可达（实际最高 1475/820/549，利用率 5.5%–14.8%）→ 对当前分数标尺是死代码；客户端伪造 9999 也只给 `(0.6I+20)*99.99` ≈ 100s 挂机（引擎有 cap，风险低） | `exploitAudit`：9999 与 1e9 同奖励、best 记 9999 |
| 重复提交 | 第 4 次被 `played` 挡住 ✓ | 实机强度用尽后 `played=3`、按钮全 disabled、`0/3` |
| **中途退出不消耗次数** | **可无限重开刷分**（Esc/关闭 → stopPlay 不调 onFinish）→ 每日 3 次上限失效；与“0 分也消耗次数（防反复重开）”设计自相矛盾 | 实测 played 1→1（live-evidence）、0→0（live-drop-cycle） |
| 0 分消耗次数 | 成立 ✓（实测 coffee 0 分后 played+1、奖励 0）；但早期 1–4 分奖励即 0 仍耗次数 | `zeroRewardScore`：idle≤1 时 minScoreForOneReward=5 |

## 4. 问题清单

### P0
1. **接咖啡视觉与判定完全错位（不可玩）**：`arcade.ts:131-150` 掉落元素只在创建时设一次 `top`、400ms 后 `setTimeout` 移除，无逐帧更新；`.drop` 无动画。实测元素寿命 400–402ms、200ms 后 top 不变、首帧 4 个元素 top 26.2%/46.7%/67.7%/87.1%；元素创建后 2.99s（正是其判定窗口中心 at±0.32s）已移除、场景 0 个掉落。截图 `live-coffee-drop-bottom.png`（29.9s 有静止方块）vs `live-coffee-at-catch-window.png`（26.9s 空场）。后果：只能盲点（期望 150–382 分）。
2. **找老板不是 30 秒游戏**：`arcade.ts:164` 固定 5 轮；实测 5 连点 0.3ms 结束、整局 377ms、得分 548。满分构成 5×50 + floor(leftSec×10) ≈ 550，**时间奖励占 55%**，分数由手速决定、上限锁死。
3. **奖励跨阶段漂移 34 倍**：早期 10.1× 30s 挂机（303s 挂机收益/局），后期仅 0.295×（8.9s）；开局 49.3×（1480s）。根因是公式固定 +20 项在低 idle 期绝对主导。与引擎注释“≈18 秒挂机收益”差 82×（开局）到 0.49×（后期）。

### P1
4. **中途退出不消耗次数** → 每日 3 次上限可被无限重开绕过；并让“0 分消耗次数”的防刷意图失效/激励反转（主动退出免费、0 分提交反而扣次数）。
5. **分数标尺与 9999 上限错配 6.8–18 倍**：实际最高 1475/820/549，cap 利用率 5.5%–14.8%；按 18s 挂机目标后期需 ~2999 分（不可达）。后期奖励仅 cap 设计值的 1/6.8。
6. **咖啡漏接惩罚失效**：`arcade.ts:132-142` 漏接计数在 `d.id <= lastIdx` 之后永不可达；引擎复刻 200 局 7264 个掉落经过 → missed=0。`coffeeScore` 的 -2/漏与 combo 断连形同虚设。
7. **三游戏标尺失衡 → 唯一最优**：节奏乱点保底 590 > 找老板理论上限 550（实机 250ms 乱点得 590 分）；三选一退化为假选择。
8. **节奏 UI 分与引擎分口径差 25%**：`arcade.ts:228/244` 额外 +perfect×5（引擎 judgeBeat 每 perfect 20）；满分 1475 vs 1180。且无 miss 惩罚，乱点保底 590（满分 40%），技巧区间被压缩到 590–1475。

### P2
9. `GAMES.dailyLimit=3`（每游戏）是死配置：实际用共享 `ARCADE_DAILY_LIMIT=3`，UI 从不读该字段 → 语义误导。
10. 奖励基数口径不一致：奖励用 `stationIdleScaled`（不含同事），HUD 显示 `effectOf`（含同事固定 + 30% 工位占比）→ 后期满队时玩家看到挂机率高于奖励基数约 30%。
11. 低分白玩：idle≤1 时 1–4 分奖励 0 仍消耗次数。
12. `best`（最高分）无任何联动：仅展示，无奖励/成就/排行；跨日保留。
13. 咖啡满分随种子浮动 24%（660–820），最高分不公平；首帧 4 个掉落齐闪。
14. 跨日重置依赖本地日期，改系统时钟可多刷 3 次（单机 P2）。

## 5. 建议（若要改数值）
- 修咖啡渲染（逐帧 top 或 CSS 动画）+ 修漏接计数。
- 找老板改为 30 秒内循环，或把时间奖励权重从 ×10 降到 ×1，使分数标尺与节奏同级（≈1500）。
- 奖励去掉固定 +20，改为纯 `idle × score/100 × k`（k≈1.2 → 满分≈18s 挂机，各阶段一致）；系数按实际分数上限归一，或把 cap 改为 ~1500 并同步调系数。
- 退出即消耗次数（或仅在结算后允许离开）；删除/落地 `dailyLimit`；节奏 UI 去掉 +perfect×5。
